The test format

One JSON (or YAML) document per test. Four question types. Ask an LLM to write one: copy the prompt below, add your topic, and drop the answer straight into Proctor. The same spec lives at /llms.txt for agents. 


        

          
Field notes

          
    
            
  • type: single (one correct option), multi (several), truefalse, or fill (typed answer)
    • 
            
  • answer: option index (0-based) or the option text itself; a boolean for truefalse
    • 
            
  • answers: array of indexes or texts, for multi
    • 
            
  • accept: accepted strings for fill, compared case-insensitively
    • 
            
  • explanation: the correction shown after answering; write it like feedback, not a citation
    • 
            
  • domain / subdomain. The blueprint grouping; chips on each question, filters before a run and in Review, and their own score breakdowns
    • 
            
  • domains (top level): { name, description, subdomains }. The description is where shared scenario context goes, written once: Proctor shows it as a fold-out panel above the question, so it must not be repeated inside each prompt
    • 
            
  • category: free text; scores roll up per category on the results screen
    • 
            
  • timeLimitMinutes, passingScore, optional, used by simulator mode
    • 
            
  • YAML works too: same fields, plain indentation only (no anchors, no inline maps)
    • 
            
  • Markdown in prompt, options, explanation, and notes: **bold**, *italic*, `code`, fenced ``` blocks, links, lists (options: inline only)
    • 
            
  • ensure: true, question always survives a "Draw N" random slice
    • 
            
  • Also imports Aiken and GIFT (Moodle) and CSV, header row prompt,options,answer,…, options |-separated
    • 
            
  • Embed a test anywhere: ?embed=1&mode=study&draw=N#t=… in an iframe, chromeless, auto-starts, saves nothing
    •
