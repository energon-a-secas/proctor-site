# CLAUDE.md: Proctor

Proctor: exam runner loading tests from JSON/YAML; study mode with corrections, timed simulator with palette. Questions group by domain/subdomain/category: a top-level `domains` registry gives each domain a description, which is where shared scenario context goes *once* (rendered as a fold-out panel above the question, a banner in Review). The field whose absence made generators paste the scenario into every prompt. The same facets filter a run before it starts and filter Review, and score breakdowns are per facet. llms.txt format spec for LLM-generated tests (proctor.neorgon.com)

**Live:** proctor.neorgon.com · **Port:** 8861

## Run

```bash
make serve
```

Then open http://localhost:8861. It must be served over HTTP. The app is ES modules, and `file://` blocks them.

## Conventions

- Zero build step. Plain ES modules loaded by `js/app.js`.
- Header and footer come from the shared kits. Do not add site-local `.neo-footer` or `.header-bar` CSS.
- The fleet guideline is ~500 lines per module; `js/render.js`, `js/events.js` are already past it. Split when touching them, do not grow them further.
- `js/app.js` is 89 lines against a 50-line guideline; it should be an entry point, not a module.
